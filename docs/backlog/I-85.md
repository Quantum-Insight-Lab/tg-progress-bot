# I-85. infra — логгер: механизм, уровень info, вход и ход процесса

## Уже есть

- I-02 — один процесс: webhook Telegram, планировщик, части Progress Engine · B-1, B-2, B-3, B-12

## Зачем

Владелец хочет видеть, как работает процесс, на уровне `info`, не открывая журнал событий (B-17). Логгер в реестре механизмов `AGENTS.md` — «появится»: первая задача, которой он нужен, — эта.

## Что найдено

- после развёртывания 30.09 `docker logs progress-app-1` пуст: `src/main.ts` и `src/process.ts` не пишут ничего, даже о старте;
- отказ обработчика webhook отвечает `500` и теряется: `startTelegramWebhook` вызывает `fail(res)`, причина никуда не пишется;
- `startSchedulerLoop` отбрасывает итог хода вместе со списком `failed`; `startReconcileLoop` глотает отказ хода сверки;
- в v1 логгер был (#3), в v2 его нет.

## Сделать

- механизм `src/infrastructure/logger.ts`, один на процесс: уровни `debug`, `info`, `warn`, `error`; уровень — `LOG_LEVEL`, по умолчанию `info`, неизвестное значение — отказ старта; переменная — в `.env.example` и `docker-compose.yml`;
- запись — одна строка JSON в stdout: время ISO, уровень, шаг, поля; без новой зависимости — пакет только по согласованию отдельным коммитом (запрет 9);
- логгер доходит до адаптеров параметром из `src/process.ts`; если его тип нужен `src/telegram` и `src/github` — порт рядом с `Clock` в `src/domain/shared`; домен в лог не пишет;
- секреты не попадают в запись: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `GITHUB_WEBHOOK_SECRET`, `GITHUB_APP_PRIVATE_KEY`, пароль из `DATABASE_URL`, заголовки секрета и подписи;
- решение владельца о тексте людей — название задачи, причина блокера, аргумент команды: по умолчанию не пишется; писать ли его на `debug`. I-86 и I-88 следуют этому решению;
- старт: порт, хост, пути webhook, интервалы планировщика и сверки, подключён ли GitHub App; стоп: сигнал и итог закрытия;
- вход HTTP: метод, путь, код ответа, длительность; `401` и `404` — `info`, `500` — `error` с причиной;
- ход планировщика: какие слоты отработали, отказ слота — `error` с его ID; тик, пропущенный из-за незаконченного хода, — `debug`;
- ход сверки на уровне цикла: начало, конец, длительность, отказ — `error`; подробности по репозиториям — I-87;
- `AGENTS.md`: «Логирование» — «есть».
