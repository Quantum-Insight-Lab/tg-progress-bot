## Сделать

- runbook «после сборки» в `deploy/README.md`, каждый шаг — команда и ожидаемый результат:
  - `npm run ci` зелёный, образ собран, `migrate` печатает применённые миграции или «уже применены»;
  - `app` поднят, в логе строка старта без секретов;
  - `PUBLIC_HOST` отвечает по HTTPS сертификатом своего имени;
  - `getWebhookInfo`: адрес — `PUBLIC_WEBHOOK_ORIGIN` + `/telegram/webhook`, `pending_update_count` не растёт; `last_error_message` не критерий — Telegram не стирает текст прошлой ошибки;
  - ping GitHub App → `2xx`, в логе строка доставки;
  - `/start` в личке корня → ответ, в логе путь: обновление, guard, событие, ответ;
  - за интервал в логе виден ход планировщика и ход сверки;
- решение владельца 01.10: `npm run smoke` (`src/smoke-main.ts`, сервис `smoke` в профиле `tools`, строка реестра механизмов) — шаги без людей и итог одной строкой; runbook остаётся для шагов с человеком. Проход runbook на хосте и итог в issue записывает владелец;
- адрес здоровья `GET /healthz`: `200` и пустое тело, когда процесс жив и `SELECT 1` проходит, иначе `503`. Caddy и nginx его не проксируют. healthcheck `app` в compose. Строка `http.request` пишется на каждый опрос (B-17, INV-16).
