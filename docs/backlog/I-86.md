# I-86. events — логи журнала: каждое событие и повтор по ключу

## Уже есть

- I-01 — журнал событий: `emit`, конверт, идемпотентность, схемы из реестра · INV-22, INV-28 · E-17 · B-4, B-14 · S-3
- I-85 — логгер: механизм, уровень info, вход и ход процесса · B-17 · B-2, B-3 · S-4 · M-18 · A-28, A-29, A-30, A-31, A-32, A-33, A-35, A-36, A-42, A-44, A-45 · события `scheduler.missed`

## Зачем

Команда, доставка GitHub и ход планировщика заканчиваются записью в журнал. Строка лога на каждое событие показывает путь целиком, не открывая БД.

## Что найдено

- `emit` пишет через порт `EventJournal`; реализация — `createEventJournal` в `src/infrastructure/event-journal.ts`;
- S-1 запрещает `src/events` импортировать инфраструктуру и домен: строку пишет реализация журнала, а не `src/events/emit.ts`;
- в реестре 51 тип события; повтор по ключу — `delivery.duplicate` (M-7); в лог сейчас не попадает ни то, ни другое.

## PDA

B-17 · INV-22, INV-28 · M-7 · события `delivery.duplicate`

## Атомы ТЗ

Нет: работа derived, её содержание — элементы PDA выше.

## Сделать

- записанное событие — `info`: тип, версия, ключ идемпотентности, субъект, correlation и causation; из payload — ID и коды, текст людей — по решению из I-85;
- повтор по ключу — `info` с тем же ключом и пометкой повтора;
- отказ схемы payload до записи — `warn`: тип и путь поля из ошибки схемы, без значения;
- отказ транзакции журнала — `error` с типом события и причиной.

## Не делать

- дублировать журнал в лог целиком: payload остаётся в БД;
- писать в лог из `src/events` в обход S-1.

## DoD

- тест по реестру: для каждого типа из `EVENT_TYPES` запись даёт строку `info`, повтор — строку повтора;
- `npm run ci` зелёный, ни одна проверка не ослаблена.
