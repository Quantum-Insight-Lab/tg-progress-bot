# I-89. infra — развёртывание: перезапуск, том журнала, внешний прокси, webhooks из образа

## Уже есть

- I-82 — развёртывание: образ, секреты, webhooks Telegram и GitHub · B-2, B-4, B-5, B-11, B-12, B-13

## Зачем

Развёртывание 30.09 на `progress.qip.zone` заняло несколько минут, но от описанного в I-82 пришлось отступить дважды, а ещё три пробела грозят работе бота, журналу и диску.

## Что найдено

- Caddy из `docker-compose.yml` не встаёт, когда 80 и 443 заняты: на хосте их держит nginx; прокси — nginx хоста на `127.0.0.1:8088`, сертификат — certbot, порт открыл `docker-compose.override.yml`, которого нет в git; вариант «внешний прокси» не описан;
- `npm run register-webhooks` требует Node на хосте, а его там нет; сервис `app` не получает `PUBLIC_WEBHOOK_ORIGIN`; сработал запуск образа с `.env`: `docker run --rm --env-file .env progress-app node … src/register-webhooks-main.ts`;
- у сервисов нет `restart`: после перезагрузки хоста или падения процесса бот сам не поднимается;
- данные Postgres — в безымянном томе: `docker compose down` и новый `up` дают пустую базу, журнал событий остаётся в брошенном томе (INV-28), копии нет;
- у контейнеров нет ротации логов: при `info` на всех путях (B-17) диск растёт без предела.

## PDA

B-2, B-3, B-4, B-5 · INV-28

## Атомы ТЗ

Нет: работа derived, её содержание — элементы PDA выше.

## Сделать

- `restart: unless-stopped` у `postgres`, `app` и `caddy`; `migrate` — по-прежнему отдельный шаг;
- именованный том данных Postgres; решение владельца о копии журнала: `pg_dump` по расписанию хоста или без копии с записанным риском;
- вариант «внешний прокси» в git: Caddy не поднимается, порт `app` — только на `127.0.0.1`, пример nginx для обоих путей webhook; как выбирается вариант — профиль compose или отдельный файл;
- `register-webhooks` из образа, с окружением из `.env`: команда в compose или в runbook I-90;
- ротация логов контейнеров: размер и число файлов;
- `tests/deploy.test.ts` сверяет новые поля compose так же, как сверяет Caddyfile.

## Не делать

- выдумывать хостинг: хост, домен и прокси задаёт владелец;
- класть секреты в репозиторий и в compose.

## DoD

- на хосте с занятыми 80 и 443 бот поднимается по документу без файлов вне git;
- `docker compose down` и `up` сохраняют журнал;
- `npm run ci` зелёный, ни одна проверка не ослаблена.
