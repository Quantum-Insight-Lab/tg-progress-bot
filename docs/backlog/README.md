# Backlog

## Правила

1. **Issue ссылается на атомы и на элементы PDA.** Атомы — чек-лист «Атомы ТЗ», элементы — раздел «PDA». Метка в чек-листе — подсказка; текст атома — в ТЗ по якорю, вся цепочка — `npm run tz:trace -- R-xxx`.
2. **Одна issue — один контекст** (9.6). Фича через два контекста режется по событию: один контекст публикует, другой подписывается. Общий атом входит в обе issue и сдан, когда закрыты обе (10.11): так R-251 стоит в I-09 и I-38.
3. **В issue не больше `MAX_ATOMS_PER_STEP` атомов** (TR-8). Больше — режется по атомам, а не по слоям.
4. **Каждый покрытый атом MVP назначен issue** (TR-7). У закрытой issue (`state: closed`) отмечены все атомы; неотмеченный — новая issue или `clarify`, не «почти готово».
5. **PR** — `Closes #N` и список закрытых атомов.

`npm run tz:check` проверяет TR-7 и TR-8 блокирующе, а ссылки на атомы, элементы PDA, `blocked_by` и этот каталог — по TR-2.

## Размер шага

| Поле | Значение |
| --- | --- |
| Название | `MAX_ATOMS_PER_STEP` |
| Тип | лимит |
| Зачем нужна | держит шаг в пределах, которые исполнитель реализует целиком |
| Значение | 10 — значение патча без данных ретрофита: ТЗ v2 написано заново, ретрофита не было |
| Допустимый диапазон | 5–25 |
| Как калибруем | `underdelivery_rate` (M-23) по размеру issue: порог — размер, после которого доля недоданных атомов растёт |
| Риск, если завышена | недодача возвращается: шаг снова больше мощности агента |
| Риск, если занижена | шагов много, растёт стоимость сшивки и приёмки |
| Где живёт | `MAX_ATOMS_PER_STEP` в `scripts/tz-check.ts` |
| Владелец | архитектор |
