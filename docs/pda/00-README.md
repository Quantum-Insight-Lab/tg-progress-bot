# Пакет PDA

**Проект:** Прогресс-бот v2 — задачи в Telegram с зеркалом GitHub.
**Корень трассы:** ТЗ [`docs/tz.md`](../tz.md) с якорями `{R-xxx}` и реестр атомов [`contracts/tz-registry.yaml`](../../contracts/tz-registry.yaml).

ТЗ отвечает на вопрос, что делает продукт. Пакет отвечает на три других: какие факты система создаёт, что в ней истинно всегда и чем каждое «всегда» обеспечено. Правило пакета — инвариант без механизма обеспечения остаётся пожеланием (PDA 8); требование без адреса — тоже (патч 1.3, 10.1).

## Чем проверяется

`npm run ci` — всё блокирующе, кроме S-7:

- `tz:check --gate --pda`: TR-1…TR-5, TR-7, TR-8 и gate D-1…D-6 — ТЗ, реестр, элементы PDA, реестр событий и backlog ссылаются друг на друга без дыр;
- инварианты сборки S-1…S-3, S-5, S-6, S-8, S-10; S-7 — отчётом до появления тестов домена ([09](09-structural-invariants.md)).

## Что осознанно не делается

Отказ записывается, иначе он неотличим от «забыли» (патч 1.3, 10.2).

| Что | Почему | Когда вернуться |
| --- | --- | --- |
| Шаг 8 и Experiment Cards (5.6) | до запуска калибровать нечего: пороги из 05 заданы экспертно | после приёмки MVP — по M-1, M-2, M-5, M-6 и связкам контура обратной связи в 08 |
| Stability Engine отдельным компонентом (4.1) | анти-абуза и экономики нет, бот отвечает только участникам (INV-16); устойчивость — идемпотентность, лимиты и доступ в домене, B-16 в 07 | если появятся внешние пользователи или платные операции |
| Метрика anomaly rate (шаг 7, A2) | чужие боту не пишут; попытки видны как `access.denied` и в M-12 | вместе со Stability Engine |
| Graph change lead time (9.10) | исполнитель один, решения архитектора идут в том же диалоге | при втором параллельном исполнителе |
| Микросервисы | разделение до стабилизации домена разрушает целостность (PDA 8); B-3 — один процесс | после стабилизации домена и по метрикам нагрузки |
| TR-6, TR-9, `tz.lock`, `tz:impact` | «по мере боли» (10.16): первые строки внедрения — TR-1…TR-5, TR-7, TR-8 — уже блокируют | TR-9 — при первой правке текста атома после старта кода |
| S-4 и S-9 | в реестр только вместе с проверкой, а проверять пока нечего | S-4 — с первыми механизмами БД, логгера и клиентов; S-9 — когда кода станет больше каркаса (I-81) |
| Полные карточки 5.3 для всех 28 INV | развёрнуты четыре с максимальной ценой ошибки; остальные поля шаблона закрыты общими механизмами | если по какому-то INV случится доменный инцидент |
