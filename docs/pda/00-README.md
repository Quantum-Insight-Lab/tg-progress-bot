# Пакет документации перед разработкой

**Проект:** Прогресс-бот — задачи в Telegram с интеграцией GitHub.
**Основание:** ТЗ [`Прогресс-бот.md`](../archive/Прогресс-бот.md), методология PDA v1.1, патч PDA v1.2 (инварианты сборки).

ТЗ отвечает на вопрос «что делает продукт». Этот пакет отвечает на три других:

- какие факты система создаёт и из чего они складываются (граф домена, события);
- что в ней обязано быть истинно всегда (инварианты);
- чем каждое «обязано» обеспечено (механизм: валидатор, constraint, тест, проверка в CI).

Правило, из которого собран пакет: **инвариант без механизма обеспечения — это пожелание** (PDA 8, патч 9.1).

## Что осознанно не делается

| Что | Почему |
| --- | --- |
| Experiment Cards (PDA шаг 8) | до запуска калибровать нечего: пороги из [05](05-constants.md) заданы экспертно, первые эксперименты — после MVP по метрикам из [08](08-observability.md) |
| Раздел 9.6 патча: деление по bounded context между исполнителями, зона архитектора, метрика graph change lead time | исполнитель один, узкого места из двух агентов не возникает; вес переносится на `AGENTS.md` и блокирующие проверки |
| Микросервисы | домен не стабилизирован, разделение до стабилизации разрушает целостность (PDA 8) |
| Stability Engine как отдельный компонент | анти-абуза и экономики здесь нет; устойчивость сводится к идемпотентности и лимитам, живёт в домене (см. [07](07-architecture.md)) |

Границы контекстов (S-2) при одном исполнителе всё равно проводятся: они нужны, чтобы AI-агент не срастил модули, а не чтобы делить работу между людьми.

## Технические решения пакета

Приняты по умолчанию, потому что инструментарий патча (раздел 9.3) завязан на TypeScript. Если стек меняется, файл [09](09-structural-invariants.md) переписывается целиком — там инструменты, а не принципы.

| Решение | Значение | Причина |
| --- | --- | --- |
| Язык и рантайм | TypeScript, Node 22 | `dependency-cruiser`, `madge`, `knip`, генерация Zod-схем из реестра событий |
| Telegram | grammY | типизированный Bot API, поддержка topics и инлайн-кнопок |
| GitHub | Octokit + GitHub App | приватные репозитории, проверка подписи webhooks |
| БД | PostgreSQL, Kysely | инварианты частично выражаются constraint'ами, нужен явный SQL без ORM-магии |
| Тесты | Vitest | нейминг `INV-xx` в названиях тестов для сверки со спекой (S-7) |
| Процесс | один сервис, планировщик внутри | брокер и вторая единица развёртывания не нужны при этой нагрузке |

## Порядок работы

1. Изменение домена — новая сущность, связь, событие, инвариант, константа — начинается с правки этого пакета и только потом идёт в код.
2. Новое событие добавляется отдельным коммитом в `contracts/event-registry.yaml`, не смешанным с реализацией фичи (патч 9.4).
3. Инвариант принимается только вместе с работающей проверкой; «договорились так делать» живёт в `AGENTS.md`, а это более слабый уровень надёжности.
4. Расхождение между ТЗ и пакетом трактуется в пользу пакета: ТЗ описывает поведение, пакет — законы. Расхождение фиксируется правкой ТЗ.
