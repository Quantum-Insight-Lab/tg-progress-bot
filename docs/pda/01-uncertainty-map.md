## Что отсюда следует для разработки

- U-2, U-3 и U-6 — то, чем v2 отличается от v1: доля считается только по issues, при пустых данных печатается «Нет данных», задача и issue не связаны. Упрощение, которое ломает один из трёх пунктов, ломает продукт.
- U-4 и U-5 держатся на актах людей: галочка, подтверждение, reply с причиной. Статус задачи из GitHub не выводится.
- U-12 — плата за разделение слоёв. Она закрывается видимостью, строкой расхождения, а не импортом issues в задачи.
- U-18 — единственная неопределённость системы. Из неё следует идемпотентность обработки webhooks и нажатий кнопок, которой в ТЗ нет: это решение архитектуры, на шаге 4 оно получит пометку `derived`.
- Вне карты осознанно: AI-пересказ, недельный отчёт, публичный dashboard, прогноз сроков, связь задачи с issue, передача задачи — всё это вне MVP (§12).
