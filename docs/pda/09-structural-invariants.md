> Structural Invariant Sheet (патч 1.2, 9.3 и 9.7). Инвариант сборки защищает единственность и направление механизмов, а не корректность фактов. Колонка «Из ТЗ» у всех — `derived`: инварианты сборки приходят из патча, а не из ТЗ.

# Инварианты сборки

Правило внесения: **инвариант попадает в реестр только вместе с работающей проверкой.** Договорённость без проверки живёт в [`AGENTS.md`](../../AGENTS.md) и заведомо слабее.

Исполнитель — AI-агент. Он не помнит прошлых решений между задачами и копирует ближайший образец из кода, поэтому дрейф механизмов начинается не на втором исполнителе, а на второй задаче.

## Кандидаты

Проверки ещё нет, поэтому в реестр они не входят. Номера зарезервированы, как в каталоге патча.

| Кандидат | Инвариант | Когда вводить |
| --- | --- | --- |
| S-4 | один механизм на задачу по реестру в `AGENTS.md`; тест-перепись реализаций | когда появятся клиент БД, логгер, клиенты Telegram и GitHub |
| S-9 | мёртвый код и неиспользуемые экспорты не копятся (`knip`) | когда кода станет больше каркаса |

## Карточки

Шаблон 9.7. Формулировка, «что ломается», механизм и режим — в строке реестра выше; здесь — остальные поля. Поле «легальные исключения» обязательно: без него инвариант либо обходят молча, либо он останавливает работу на первом оправданном случае. Владелец у всех — архитектор.

### S-1 — слои зависят в одну сторону

| Поле | Значение |
| --- | --- |
| Где проверяется | CI, `npm run boundaries`: правила `S-1-*` в `dependency-cruiser.config.mjs`; импорт только типов тоже считается зависимостью |
| Как выглядит нарушение | `import { bot } from '../../telegram/bot.ts'` в `src/domain/tasks` |
| Легальные исключения | нет. Домену нужна инфраструктура — порт в `src/domain/shared`, реализация в `src/infrastructure`, как у `Clock` |

### S-2 — контексты связаны событиями

| Поле | Значение |
| --- | --- |
| Где проверяется | CI, правило `S-2-contexts`: `src/domain/<контекст>` импортирует только себя и `src/domain/shared` |
| Как выглядит нарушение | `tasks` вызывает функцию из `projects`, чтобы снять задачи удалённого участника, вместо реакции на `project.member_removed` |
| Легальные исключения | нет. Общий код двух контекстов — в `src/domain/shared`; новая связь контекстов — событие в реестре, решение архитектора |

### S-3 — единственный источник имён событий

| Поле | Значение |
| --- | --- |
| Механизм | `npm run codegen:events` пишет `src/events/generated/events.ts`: `EVENT_TYPES`, `EVENT_VERSIONS`, конверт, payload каждого события, `PayloadByType`. Файл коммитится, расхождение видно в диффе |
| Где проверяется | CI: `--check` генерирует заново и сравнивает с закоммиченным; ESLint запрещает строку первым аргументом `emit` и `on` |
| Как выглядит нарушение | `emit('task.done', …)` — падает линтер; правка сгенерированного файла руками — падает `--check` |
| Легальные исключения | нет: события, которого нет в реестре, не существует |
| Дальше | схемы валидации payload добавятся в генерацию вместе с журналом событий (I-01) |

### S-5 — проекции не пишут журнал

| Поле | Значение |
| --- | --- |
| Где проверяется | CI, правило `S-5-projections-journal`: из `src/events` проекциям доступен только `src/events/generated` |
| Как выглядит нарушение | рендер канваса сам публикует `canvas.edited` — событие публикует акт системы A-31, а проекция только строит текст |
| Легальные исключения | нет |

### S-6 — циклов между модулями нет

| Поле | Значение |
| --- | --- |
| Где проверяется | CI, правило `S-6-no-circular` |
| Как выглядит нарушение | модуль канваса импортирует модуль блоков, а тот — обратно канвас за общим типом |
| Легальные исключения | нет: общий кусок выносится в третий модуль |

### S-7 — у инварианта есть тест

| Поле | Значение |
| --- | --- |
| Механизм | `scripts/check-invariants.ts` сверяет ID из таблицы 04 с началом имён `it`, `test`, `describe` в `tests/` |
| Где проверяется | CI, `npm run check:invariants` |
| Режим | отчёт, пока у инвариантов нет кода: сейчас 28 в спеке, 0 с тестом. Тест с ID, которого нет в спеке, ломает сборку уже сейчас. DoD issue требует тест на каждый затронутый INV. Когда тесты будут у всех, CI переходит на `--strict` (I-81) |
| Как выглядит нарушение | issue закрыта, INV из её раздела PDA без теста; тест назван `INV-5`, а не `INV-05` |
| Легальные исключения | нет. Засчитывается ID в начале имени, поэтому у каждого INV — свой тест или свой `describe`; INV, который держит constraint БД, тоже получает тест: миграция и попытка нарушения |

### S-8 — чисел в домене нет

| Поле | Значение |
| --- | --- |
| Где проверяется | CI: ESLint `no-restricted-syntax` на числовые литералы в `src/domain`; `tests/constants.test.ts` сверяет `src/config` с карточками 05 |
| Как выглядит нарушение | `if (daysWithoutCheck >= 2)` вместо `STALE_DAYS`; константа в `src/config` со значением, которого нет в карточке |
| Легальные исключения | 0, 1 и −1; расширение списка — отдельный коммит с обоснованием в этой карточке |

### S-10 — явная таймзона

| Поле | Значение |
| --- | --- |
| Механизм | порт `Clock` в `src/domain/shared/clock.ts`; системное время читает только `src/infrastructure/clock.ts` |
| Где проверяется | CI: ESLint `no-restricted-syntax` на `Date.now()` и `new Date()` в `src/domain` |
| Как выглядит нарушение | `const today = new Date().toISOString().slice(0, 10)` в логике канваса |
| Легальные исключения | нет в `src/domain`; вне домена время тоже берётся через `Clock`, но проверкой это не закреплено |
