> Structural Invariant Sheet (патч PDA v1.2, разделы 9.3 и 9.7). Инвариант сборки защищает единственность и направление механизмов, а не корректность фактов.

# Инварианты сборки

Правило внесения: **инвариант попадает в реестр только вместе с работающей проверкой.** «Договорились так делать» живёт в [`AGENTS.md`](../../AGENTS.md), и это заведомо более слабый уровень надёжности.

Исполнитель здесь один, но он AI-агент, и это не ослабляет требования, а меняет причину: агент не помнит прошлые решения между задачами и по умолчанию копирует ближайший образец из кода. Без S-3 и S-4 дрейф реализаций начинается не на втором исполнителе, а на второй неделе.

## Реестр

| ID | Инвариант | Что ломается без него | Механизм | Режим |
| --- | --- | --- | --- | --- |
| S-1 | `domain` не импортирует `telegram`, `github`, `projections` | доменные правила уезжают в хендлеры, домен нельзя тестировать отдельно | `dependency-cruiser` с правилами слоёв из [07](07-architecture.md) | CI, блокирующе |
| S-2 | Контексты `projects` и `tasks` общаются событиями; прямых импортов между ними нет | контексты срастаются, дальше любое изменение задевает всё | `dependency-cruiser`, отдельная зона | CI, блокирующе |
| S-3 | Каждый `event_type` есть в реестре, типы генерируются, строковых литералов в публикации нет | два имени одного факта, расхождение схем, мёртвые проекции | генерация из `contracts/event-registry.yaml` + `no-restricted-syntax` на литералы в `emit` | CI, блокирующе |
| S-4 | Один механизм на задачу: один клиент БД, один логгер, одна точка конфигурации, один способ ошибок, один HTTP-клиент | дрейф реализаций, агент копирует ближайший образец | реестр механизмов в `AGENTS.md` + тест-перепись реализаций | CI, блокирующе |
| S-5 | Проекции не пишут в журнал событий | тихая порча инвариантов, журнал перестаёт быть источником правды | правило границ на каталог `projections` | CI, блокирующе |
| S-6 | Нет циклических зависимостей между модулями | порядок сборки неопределён, рефакторинг блокируется | `madge --circular` | CI, блокирующе |
| S-7 | Каждый инвариант домена имеет тест, ссылающийся на его ID | инвариант остаётся текстом в спеке | конвенция `INV-xx` в имени теста + `scripts/check-invariants.ts`, сверяющий [04](04-invariants.md) с тестами | CI, блокирующе |
| S-8 | Константы читаются только из `src/config` | пороги расползаются по коду, калибровка становится невозможной | запрет числовых литералов в `src/domain` со списком исключений | CI, блокирующе |
| S-9 | Мёртвый код и неиспользуемые экспорты не накапливаются | агент дублирует то, что уже есть, но не видит | `knip` | CI, предупреждение |
| S-10 | Все даты в домене обрабатываются с явной таймзоной проекта | «сегодня» считается в таймзоне сервера, список дня и отчёты уезжают на сутки | запрет `new Date()` и `Date.now()` в `src/domain`, только инжектируемый `clock` | CI, блокирующе |

S-10 добавлен к каталогу патча: у этого продукта границы суток определяют три механизма сразу — список дня, порог застоя и расписание отчётов, — и ошибка в таймзоне не ловится ни одним доменным тестом, если тест написан в той же таймзоне.

## Развёрнутые карточки

### S-3 — единственный источник имён событий

| Поле | Значение |
| --- | --- |
| Формулировка | Каждый `event_type` существует в `contracts/event-registry.yaml`; типы и схемы генерируются из него; строковые литералы типов в коде запрещены |
| Что ломается без него | появляются `task.checked` и `taskChecked`, схемы расходятся, проекция подписана на имя, которого больше никто не публикует |
| Механизм | `npm run codegen:events` создаёт `src/events/generated/`; каталог в `.gitignore` нет — он коммитится, чтобы расхождение было видно в диффе; `eslint no-restricted-syntax` запрещает строковый аргумент в `emit` и `on` |
| Где проверяем | CI: генерация запускается заново и сравнивается с закоммиченным результатом; расхождение ломает сборку |
| Режим | блокирующе с первого дня |
| Как выглядит нарушение | `emit('task.done', ...)` — имени нет в реестре, линтер и компилятор падают оба |
| Легальные исключения | нет. Событие, которого нет в реестре, не существует |
| Владелец | архитектор |

### S-4 — один механизм на задачу

| Поле | Значение |
| --- | --- |
| Формулировка | Для каждой инфраструктурной задачи существует ровно одна реализация, перечисленная в реестре механизмов `AGENTS.md` |
| Что ломается без него | второй способ обработки ошибок, второй клиент Telegram, вторая точка чтения конфигурации; дальше каждый следующий агент выбирает случайный образец |
| Механизм | тест-перепись: считает число модулей, экспортирующих ключевые механизмы (клиент БД, логгер, конфиг, Telegram-клиент, Octokit-клиент, класс ошибки домена). Больше одного — падение |
| Где проверяем | CI |
| Режим | блокирующе |
| Как выглядит нарушение | второй файл, создающий `new Pool(...)` или свой `fetch` к Telegram API |
| Легальные исключения | тестовые дублёры в `tests/`, каталог исключён из подсчёта |
| Владелец | техлид |

### S-8 — константы только из конфигурации

| Поле | Значение |
| --- | --- |
| Формулировка | Числовые литералы в `src/domain` запрещены, кроме списка исключений; пороги и коэффициенты приходят из `src/config` |
| Что ломается без него | `STALE_DAYS` оказывается вписанным в три места с разными значениями, калибровка перестаёт быть возможной |
| Механизм | `eslint no-magic-numbers` для `src/domain` |
| Где проверяем | CI |
| Режим | блокирующе |
| Как выглядит нарушение | `if (daysSinceCheck > 2)` вместо `if (daysSinceCheck > config.staleDays)` |
| Легальные исключения | `0`, `1`, `-1` и индексы массивов; расширение списка — отдельный коммит с обоснованием в этом файле |
| Владелец | архитектор |

### S-10 — явная таймзона

| Поле | Значение |
| --- | --- |
| Формулировка | В `src/domain` нет прямого обращения к системному времени; текущий момент и календарная дата приходят через `clock` с таймзоной проекта |
| Что ломается без него | список дня создаётся дважды на границе суток, порог застоя считается по таймзоне сервера, отчёт уходит не тогда, когда ждут |
| Механизм | `eslint no-restricted-globals` и `no-restricted-syntax` на `Date.now()`, `new Date()` без аргументов в `src/domain`; единственная реализация `clock` (входит в реестр механизмов S-4) |
| Где проверяем | CI |
| Режим | блокирующе |
| Как выглядит нарушение | `const today = new Date().toISOString().slice(0, 10)` внутри логики списка дня |
| Легальные исключения | `src/infrastructure/clock.ts` — единственное место, где читается системное время |
| Владелец | архитектор |

## Порядок внедрения

Из патча 9.11, с поправкой на одного исполнителя: пункт про деление задач по контекстам и протокол расширения графа сводится к правилу остановки в `AGENTS.md`.

**Первый день, до первой фичи:**
1. S-1, S-2 — правила границ, один конфиг `dependency-cruiser`, блокирующий режим сразу.
2. S-3 — реестр событий, генерация, запрет литералов.
3. S-10 — запрет системного времени в домене и единственный `clock`.
4. `AGENTS.md` с реестром механизмов и Definition of Done.

**Первая неделя:**
5. S-7 — сверка инвариантов с тестами: сначала отчётом, затем блокирующе.
6. S-8 — константы из конфигурации.

**По мере появления боли:**
7. S-4, S-5, S-6, S-9 и метрики слоя «Сборка» на дашборд.

Правило остановки из патча сохраняется: пункт 7 не начинается, пока 1–6 не работают в блокирующем режиме. Реестр инвариантов сборки без механизмов возвращает методологию к состоянию пожеланий.
