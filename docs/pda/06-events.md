# События

Источник правды — [`contracts/event-registry.yaml`](../../contracts/event-registry.yaml). Этот файл объясняет правила работы с ним и показывает картину целиком; при расхождении прав реестр.

## Правила

1. **Типы генерируются из реестра.** Скрипт собирает TypeScript-типы и Zod-схемы; ручное объявление типа события — ошибка сборки (S-3).
2. **Строковых литералов в публикации событий нет.** `emit('task.checked')` запрещён линтером, используется сгенерированная константа.
3. **Новое событие — отдельный коммит**, не смешанный с реализацией фичи, с одновременной правкой [04-invariants.md](04-invariants.md), если событие затрагивает инварианты.
4. **Схема существующего события не правится.** Изменение — только `version + 1`, потому что в журнале уже лежат факты предыдущей версии. Обработчик обязан уметь читать все живые версии.
5. **Событие без инвариантов — сигнал ошибки проектирования.** Значит, неопределённость, которую оно закрывает, не сформулирована (PDA шаг 1). Исключение — чисто зеркальные события контекста `github`, у них указаны INV-08 и INV-09.

## Конверт

Единый для всех событий, поля из PDA 4.4. Три поля, которые чаще всего забывают и без которых журнал бесполезен:

- `causation_id` — какое событие вызвало это. Позволяет ответить «почему задача оказалась заблокирована» одним запросом вместо чтения логов.
- `correlation_id` — сквозной идентификатор цепочки: нажатие кнопки, изменение задачи, пересчёт прогресса, отправка отчёта.
- `idempotency_key` — единственная защита от двойного применения факта (INV-08). Для каждого события ключ задан в реестре явно.

## Карта событий

| Событие | Контекст | Кто инициирует | Что меняет |
| --- | --- | --- | --- |
| `task.created` | tasks | человек | появляется задача в дне или в плане |
| `task.prioritized` | tasks | человек | меняется вес задачи, значит и прогресс |
| `task.reassigned` | tasks | `lead` | меняется адресат вопроса о блокере |
| `task.postponed` | tasks | человек | задача уходит из дня в очередь |
| `task.checked` / `task.unchecked` | tasks | исполнитель | задача входит и выходит из `REVIEW` |
| `task.confirmed` | tasks | `lead` | задача становится `DONE`, растёт прогресс |
| `task.cancelled` | tasks | человек | задача покидает знаменатель прогресса |
| `task.carried_over` | tasks | система | незакрытый пункт переезжает в новый день |
| `blocker.detected` | tasks | система | зафиксирован факт застоя, задан вопрос |
| `blocker.declared` | tasks | исполнитель | у блокера появилась причина |
| `blocker.dismissed` | tasks | исполнитель | причины нет, задача возвращается в работу |
| `blocker.resolved` | tasks | система | блокер закрыт: работа пошла или задача отмечена |
| `project.member_added` / `removed` | projects | `lead` | меняется доступ |
| `github.issue_updated` | github | GitHub | состояние issue, этап, assignee |
| `github.issue_linked` | github | GitHub | зависимости, порядок плана, «Влияние» |
| `github.pull_request_updated` | github | GitHub | технический след задачи |
| `github.checks_failed` | github | GitHub | сигнал застоя по красному CI |
| `github.milestone_updated` | github | GitHub | состав и срок этапа |
| `progress.snapshot_taken` | progress | система | точка в динамике |
| `report.sent` | reports | система | факт доставки отчёта |

## Проекции

Read models строятся из журнала и пересобираются с нуля (PDA 4.2). Ни одна проекция не пишет в журнал (S-5).

| Проекция | Для чего | Ключевые события |
| --- | --- | --- |
| `today_list` | сообщение со списком дня | `task.created`, `task.checked`, `task.carried_over` |
| `plan_queue` | экран «План» | `task.created`, `task.postponed`, `github.issue_linked` |
| `in_progress_board` | экран «В работе» | `task.checked`, `blocker.*`, `github.pull_request_updated` |
| `done_feed` | экран «Сделано» | `task.confirmed` |
| `blockers_board` | экран «Блокеры» | `blocker.*`, `github.checks_failed` |
| `github_state` | экран «GitHub», в том числе issues без задач | `github.*`, `task.created` |
| `project_progress` | процент и разбивка в карточке | `task.*`, `github.issue_updated` |
| `dynamics_series` | динамика по датам | `progress.snapshot_taken` |
| `daily_digest` / `weekly_digest` | тексты отчётов | все события периода |
| `access_list` | проверка членства | `project.member_added`, `project.member_removed` |

## Чего в реестре нет

- **Событий изменения GitHub ботом** — их не существует, интеграция односторонняя (INV-09).
- **`task.updated` как универсального события.** Одно событие «что-то поменялось» превращает журнал в лог и лишает его смысла: по нему нельзя ни восстановить причину, ни проверить инвариант.
- **Событий показа экранов.** Просмотр не создаёт факта о продукте; если понадобится продуктовая аналитика, она пойдёт отдельным контекстом и не смешается с доменом.
