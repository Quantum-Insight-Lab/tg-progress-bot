> Constant Cards (PDA 5.4, шаг 5). Константы конфигурируемы, но не произвольны: у каждой есть назначение, диапазон и способ калибровки. Колонка «Из ТЗ» — все атомы, чьи числа держит константа, или `derived: причина` для константы, которой в ТЗ нет (патч 1.3, 10.13).

# Константы и поверхности управления

Значения читаются только из конфигурационного слоя (патч 1.2, S-8): число из этой таблицы, вписанное в код домена, — ошибка сборки. C-1…C-7 — константы продукта: они влияют на поведение людей и калибруются наблюдением. C-8…C-11 — константы надёжности: их задают внешние системы и нагрузка.

## C-1 — STALE_DAYS

| Поле | Значение |
| --- | --- |
| Тип | порог и интервал |
| Зачем нужна | держит связь канваса с реальностью: задача, которую не отмечают, объявляет причину, а не висит молча |
| Значение по умолчанию | 2 дня |
| Допустимый диапазон | 1–5 дней |
| Как калибруем | по доле ответов «нет блокера»: больше половины — порог занижен, бот дёргает людей зря |
| Риск, если завышена | блокер всплывает, когда неделя уже потеряна: U-5 не закрыт |
| Риск, если занижена | бот становится шумом, «нет блокера» жмут механически, ответы теряют смысл |
| Владелец | архитектор |

ТЗ требует один порог на всё (R-280): застой задачи, застрявший PR, напоминание руководителю и частоту повторного вопроса. Отдельные константы для частоты — решение калибровки, а не MVP.

## C-2 — CANVAS_SLICE_SIZE

| Поле | Значение |
| --- | --- |
| Тип | лимит |
| Зачем нужна | срез issues на канвасе — короткий: «Сделано», «В работе», «Далее» по пять, чтобы канвас читался за 10–20 секунд |
| Значение по умолчанию | 5 |
| Допустимый диапазон | 3–10 |
| Как калибруем | по времени до ясности (шаг 7): растёт вместе с длиной среза — срез длинный |
| Риск, если завышена | канвас не читается с телефона и упирается в лимит сообщения (C-8, C-9) |
| Риск, если занижена | срез не показывает, что происходит в бэклоге |
| Владелец | архитектор |

## C-3 — REPORT_LIST_LIMIT

| Поле | Значение |
| --- | --- |
| Тип | лимит |
| Зачем нужна | длинные списки отчёта не вываливаются: печатается число и до пяти названий |
| Значение по умолчанию | 5 |
| Допустимый диапазон | 3–10 |

| Риск, если завышена | отчёт превращается в выгрузку |
| Риск, если занижена | из отчёта не понять, что закрыто |
| Владелец | архитектор |

## C-4 — REPORT_NEXT_TASKS

| Поле | Значение |
| --- | --- |
| Тип | лимит |
| Зачем нужна | строка «Дальше» в отчёте — до трёх задач плана по приоритету |
| Значение по умолчанию | 3 |
| Допустимый диапазон | 1–5 |

| Риск, если завышена | «Дальше» дублирует план с канваса |
| Риск, если занижена | не видно, что после текущей задачи |
| Владелец | архитектор |

## C-5 и C-6 — DYNAMICS_POINTS и DYNAMICS_STEP

| Поле | Значение |
| --- | --- |
| Тип | лимит и интервал |
| Зачем нужны | строка динамики на канвасе показывает тренд доли, а не дневной шум |
| Значение по умолчанию | 4 точки с шагом 7 дней |
| Допустимый диапазон | 2–8 точек, шаг 1–14 дней |
| Как калибруем | по тому, видит ли руководитель рост и падение доли без открытия GitHub |
| Риск, если завышена | строка длинная, старые точки ничего не говорят |
| Риск, если занижена | тренд не виден, строка бесполезна |
| Владелец | архитектор |

Снимки пишутся раз в сутки, строка берёт каждый седьмой; пропущенный снимок пропускается, а не заменяется соседним (INV-02).

## C-7 — DEFAULT_PRIORITY

| Поле | Значение |
| --- | --- |
| Тип | значение по умолчанию |
| Зачем нужна | задача заводится одной строкой, приоритет не должен быть обязательным |
| Значение по умолчанию | `normal` |
| Допустимый диапазон | одно из трёх значений |
| Как калибруем | по доле задач, где приоритет так и остался по умолчанию: если почти все — план сортируется только по дате, и это видно |
| Риск при `high` | всё важное, порядок плана перестаёт различать |
| Риск при `low` | настоящая работа тонет в конце плана |
| Владелец | архитектор |

## C-8 и C-9 — RICH_MESSAGE_MAX_CHARS и RICH_MESSAGE_MAX_BLOCKS

| Поле | Значение |
| --- | --- |
| Тип | лимиты внешней системы |
| Зачем нужны | канвас — одно rich message; за пределом Telegram отклоняет правку, и бот должен сначала ужимать срезы, а потом отказывать (A-31) |
| Значение по умолчанию | 32768 символов, 500 блоков |
| Допустимый диапазон | задаёт Bot API; сверяется на шаге 6 |
| Как калибруем | по документации Bot API и по ошибкам правки сообщения |
| Риск, если завышены | правка канваса падает, человек видит устаревшее состояние |
| Риск, если занижены | бот ужимает канвас раньше нужного |
| Владелец | техлид |

## C-11 — COMMITS_TAIL_DAYS

| Поле | Значение |
| --- | --- |
| Тип | окно |
| Зачем нужна | зеркало хранит хвост коммитов, а не всю историю (R-921); хвост должен покрывать сутки отчёта, строку канваса и сигнал расхождения |
| Значение по умолчанию | 7 дней |
| Допустимый диапазон | 1–30 дней, не меньше суток отчёта |
| Как калибруем | по размеру таблицы и по окну недельного отчёта, когда он войдёт в работу |
| Риск, если завышена | таблица растёт без пользы |
| Риск, если занижена | счётчик коммитов за сутки и сигнал расхождения теряют данные |
| Владелец | техлид |
