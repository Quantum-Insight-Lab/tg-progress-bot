# Наблюдаемость

## Критерий успеха

Главная метрика продукта — из §13 ТЗ. Бот не видит, сколько человек читал канвас, поэтому она меряется на приёмочной сессии: человек открывает свой топик, через 20 секунд канвас закрывают и задают пять вопросов.

| ID | Метрика | Как считается | Норма и о чём говорит | Из ТЗ |
| --- | --- | --- | --- | --- |
| M-1 | `time_to_clarity` | от открытия топика до ответа на пять вопросов о состоянии, без GitHub и без вопросов разработчикам | 10–20 секунд. Дольше — канвас перегружен: смотреть C-2, C-5, C-6 и состав P-1 | R-951, R-952 |
| M-2 | `clarity_answers` | доля верных ответов на пять вопросов: доля проекта, сколько осталось, где в бэклоге человек, какие задачи на нём сегодня, что блокирует | 5 из 5. Ошибка в одном вопросе указывает, какая часть канваса не читается | R-953, R-954, R-955, R-956, R-957 |

## Доменные инциденты

Доменный инцидент — не пятисотка, а состояние, в котором факты системы противоречат друг другу (PDA A2).

| Класс | Пример | Реакция |
| --- | --- | --- |
| Нарушение инварианта дошло до состояния | задача `DONE` без подтверждения руководителя (INV-06) или с открытым блокером (INV-11) | остановить обработку, восстановить состояние из журнала, добавить тест с ID инварианта |
| Двойное применение факта | два снимка доли за сутки, два отчёта в одно время (INV-22) | найти отсутствующий ключ идемпотентности, добавить уникальный индекс |
| Доля в снимке не совпала с пересчётом | снимок и зеркало дают разные числа (INV-01) | снимок не переписывается (INV-28), расчёт чинится, следующий снимок верен |
| Зеркало отстало от GitHub | issue закрыт давно, а доля прежняя (M-8) | догнать сверкой, проверить доставку webhooks |
| Канвас разошёлся с задачами | сообщение не отражает состояние в БД | пересобрать проекцию P-1 из журнала |
| Утечка доступа | удалённый участник получает канвас или отчёт (INV-16) | отозвать доставку, проверить guard |

Порядок разбора: зафиксировать событие, найти затронутый инвариант, восстановить состояние пересборкой проекции, добавить тест с ID инварианта и только потом закрыть инцидент. Тест без причины закрепляет симптом.

## Алерты

Алертов мало: бот не критичен по времени, ночные оповещения о нём вредны. Алерты уходят корню.

| Условие | Когда | Почему |
| --- | --- | --- |
| M-11 `invariant_violations` > 0 | сразу | домен противоречив, дальше данные только портятся |
| M-19 `report_delivery_failures` > 0 | сразу | на отчёт рассчитывают |
| M-18 `scheduler_missed_runs` > 0 | сразу | планировщик — единственный источник действий системы |
| M-8 `mirror_lag` больше двух `RECONCILE_INTERVAL` | сразу | webhooks и сверка молчат, доля и CI врут |
| M-17 `github_rate_remaining` < 20% | дневная сводка | запас есть, реакция подождёт |
| M-10 `no_data_share` высокая | недельная сводка | это разговор о процессе, а не инцидент |

## Контур обратной связи

Метрики нужны, чтобы менять решения. Четыре связки проверяются раз в месяц:

1. M-5 и M-6 → пересмотр `STALE_DAYS` (C-1).
2. M-1 и M-2 → длина срезов (C-2), динамика (C-5, C-6) и состав канваса (P-1).
3. M-4 и частота `review.reminded` → узкое место у руководителей: второй руководитель или другой порядок подтверждения.
4. M-20…M-24 → гигиена цепочки ТЗ → PDA → backlog: непокрытое, достроенное и недоданное.
