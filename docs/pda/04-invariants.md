> Invariant Spec Sheets (PDA 5.3, шаг 4). Инвариант без механизма обеспечения — пожелание. Колонка «Из ТЗ» — атомы вида rule, которые инвариант покрывает, или `derived: причина` для решения архитектуры (патч 1.3, TR-5). Ограничения, которые держит сама схема — уникальности, кардинальности, отсутствие связей, — покрыты графом ([03](03-domain-graph.md)).

## Развёрнутые карточки

Расписаны четыре инварианта, нарушение которых подрывает доверие к продукту: цифра, подтверждение, принадлежность фактов и повторная доставка.

### INV-01 — доля бэклога считается только по issues

| Поле | Значение |
| --- | --- |
| Формулировка | Доля бэклога проекта — `completed / (открытые + completed)` по issues его репозитория; ничего другого в формуле нет |
| Сфера действия | Issue, Проект, Снимок доли; акты A-26, A-17, A-32 |
| Что считается нарушением | подтверждённая задача сдвинула процент; смерженный PR или коммит сдвинул процент; `not_planned` попал в знаменатель; процент посчитан по одному milestone; общий процент — среднее по проектам |
| Механизм | одна функция расчёта читает только `issues`; общий процент считается той же функцией по множеству репозиториев без повторов |
| Где проверяем | домен |
| Тесты | property-based: любая последовательность событий задач, PR и коммитов не меняет долю; сценарные: `not_planned` вне формулы, два проекта одного репозитория — одна доля, общий процент по двум репозиториям |
| Мониторинг | расхождение доли в снимке и пересчёта из зеркала — доменный инцидент |
| Реакция | снимок не переписывается (INV-28), расчёт чинится, следующий снимок верен |
| Из ТЗ | см. сводную таблицу |
| Владелец | архитектор |

### INV-22 — один факт применяется один раз

| Поле | Значение |
| --- | --- |
| Формулировка | Повторная доставка webhook, повторное нажатие кнопки или повторный запуск задания не создают второго события и не меняют состояние |
| Сфера действия | все события; интеграция с GitHub; кнопки канваса; планировщик |
| Что считается нарушением | два `task.checked` по одному нажатию; два снимка доли за сутки; два отчёта за одно время; задача, перенесённая дважды на один канвас |

| Где проверяем | БД и домен |
| Тесты | property-based: повторная подача любого события не меняет состояние; сценарный: две доставки одного webhook дают один эффект |

| Реакция | повтор без ключа — доменный инцидент |
| Из ТЗ | R-350; derived: механизма в ТЗ нет, но без него U-18 не закрыть |
| Владелец | архитектор |
