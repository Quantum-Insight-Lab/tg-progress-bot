Строки «через» пересекаются: атом с INV и событием посчитан в обеих, в «путь к тесту» — один раз. Один атом: `npm run tz:trace -- R-xxx`.

Правило пути. Тест находится по соседнему слою, не по ID атома в коде:

- INV — название теста начинается с ID (S-7);
- E, L, A, P — ID в названии `it` / `test` / `describe`;
- имя события — отдельный токен в файле теста или `EVENT_TYPES.<ИМЯ>`;
- view — ID атома в названии теста (исключение запрета 14).

`tests/tz-check.test.ts` и `tests/codegen-events.test.ts` в индекс не входят: они цитируют реестр.

Без этого пути атом «проверяется тестом», если его ID есть в названии теста или обратная кавычка текста — поле схемы, которое продуктовый тест называет. Иначе — сессия I-93. На 30.09 без пути оставался 111 атом: тогда поиск не видел `EVENT_TYPES`, и часть reaction и act ещё не была в тестах. В отчёте число скрипта, не цифра из issue.

R-951…R-957 уже стоят в названиях тестов I-83, поэтому здесь они «проверяется тестом». Сессия I-93 их всё равно проходит: атомы общие, сданы когда закрыты обе.

54 атома сессии I-93 проверяет прогоном. Строки tech о составе процесса (R-082, R-092, R-093, R-773…R-779) на этом прогоне — «бот поднят и сценарий доходит до конца», не отдельный шаг на каждую строку схемы.
