# Прогресс-бот

Задачи ведутся в Telegram. GitHub только присылает факты (issues, PR, checks, milestone) и ничего в репозитории не меняет. Если факта нет, бот пишет «Нет данных», а не выдуманный процент.

Живой бот: `@progress_aibot`. Проект `progress-bot`, репозиторий `Quantum-Insight-Lab/tg-progress-bot`, сутки по `Asia/Tomsk`. Участник с ролью `lead` работает в личке и в группе проекта. Чужой аккаунт на любую команду получает «Нет доступа» и данных проекта не видит.

## Сервис

Процесс — контейнер `progress-bot`, слушает только `127.0.0.1:8080`. Образ пересобирать не нужно, если не менялся код.

Один Postgres, контейнер `progress-bot-pg`. Две базы в нём:

| Кто читает | Файл | База |
| --- | --- | --- |
| живой бот, `systemctl` | `/etc/progress-bot/env` | `progress_bot` |
| `npm test` на этой машине | `.env` в репозитории | `progress_bot_test` |

`.env` бот не читает и в git не входит. В него не подставлять `progress_bot`: тесты пишут временные проекты и затрут живой. Секреты процесса лежат только в `/etc/progress-bot/env`.

```bash
systemctl start progress-bot
systemctl stop progress-bot
systemctl status progress-bot
journalctl -u progress-bot -f
```

`journalctl` показывает тот же вывод, что пишет процесс. Ошибки сверки GitHub и падения старта ищите там.

Поднять контейнеры, если сервис их не поднял:

```bash
docker start progress-bot-pg
systemctl start progress-bot
```

Логи Postgres:

```bash
docker logs -f progress-bot-pg
```

Контейнер `progress-bot-pg` не удалять: данные лежат в его томе. Образ бота заново собирать не нужно, пока не менялся код.

Пересоздать базу с нуля. Сотрёт проекты, задачи и зеркало. После этого проект `progress-bot` нужно завести снова.

```bash
systemctl stop progress-bot
docker exec progress-bot-pg psql -U progress -d postgres -c "DROP DATABASE IF EXISTS progress_bot;"
docker exec progress-bot-pg psql -U progress -d postgres -c "CREATE DATABASE progress_bot OWNER progress;"
docker run --rm --network progress-bot-net --env-file /etc/progress-bot/env \
  tg-progress-bot:main node dist/scripts/migrate.js
systemctl start progress-bot
```

## Ручной прогон

Это сценарии из issue 53. Домен в этом проходе не чинить: расхождение записывается и уходит отдельной issue. CI не отключать и не переводить в предупреждение.

В конце прогона запишите, что прошло и что нет.

Бот уже на webhook. Long polling не включать.

### 1. Список дня

1. В личке или в группе проекта: `/task Краткая формулировка`.
2. Бот отвечает «Выберите issue» и показывает issues из зеркала. Нажмите один.
3. Появляется список на сегодняшнюю дату (`дд.мм`). Пункт без галочки, это задача на сегодня.
4. Нажмите галочку у пункта. Статус становится «ждёт подтверждения». Руководителю в личку приходит «Похоже, задача выполнена. Подтвердить завершение?» и кнопка «Подтвердить».
5. Нажмите «Подтвердить». Пункт в списке отмечен сделанным. Сам по себе `DONE` без этого нажатия не ставится.

Перенос через сутки. Оставьте один пункт без галочки. После полуночи по `Asia/Tomsk` снова выполните `/task …` и выберите issue. Незакрытый пункт вчерашнего списка появляется в новом дне с пометкой «день 2». Кнопки «перенести» нет: перенос делает открытие списка нового дня.

### 2. Экраны и отчёт

`/start` показывает «Выберите экран». Те же экраны командами: `/progress`, `/work`, `/done`, `/plan`, `/blockers`, `/github`.

На каждом экране внизу строка про возраст данных GitHub: «Данные GitHub: …», «Данные GitHub устарели: …» или «Данные GitHub: нет». «Нет» значит, что с запуска процесса ни один факт GitHub не записался.

`/report` в личке присылает дневной отчёт в этот же чат.

### 3. GitHub молчит

Пока ведёте задачи из пункта 1, смотрите строку возраста на экранах.

Сигнал застоя из CI (красный check, тихий PR) в живом процессе не выставляется: опрос застоя в процесс не включён, он есть только в тестах. Задачу, которую два дня не отмечали, бот сам в `BLOCKED` не переведёт. Это записать как не пройденное и не чинить в этом прогоне.

Повтор одной и той же доставки GitHub второе событие не пишет. Это уже проверено на issue №59 репозитория проекта: в зеркале одна строка, в журнале одно событие.
