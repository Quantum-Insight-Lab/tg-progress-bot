# Контракт исполнителя

Читается перед каждой задачей. Основание: [PDA v1.1](docs/archive/PDA-v1.1-methodology.md), [патч 1.2](docs/archive/PDA-patch-v1.2-structural-integrity.md) (9.5), [патч 1.3](docs/archive/PDA-patch-v1.3-atomization-traceability.md) (10.13). Требования — [`docs/tz.md`](docs/tz.md), домен — [`docs/pda/`](docs/pda/), события — [`contracts/event-registry.yaml`](contracts/event-registry.yaml), задачи — [`docs/backlog/`](docs/backlog/README.md).

Этот файл снижает частоту нарушений, обнуляют их проверки CI ([`docs/pda/09`](docs/pda/09-structural-invariants.md)). Правило без проверки обязательно так же, но надёжность у него ниже.

## Карта слоёв

```
src/telegram       → domain, projections, events
src/github         → domain, events
src/domain         → events (типы), config        ← законы живут здесь
src/projections    → events/generated, чтение БД
src/events         → config
src/infrastructure → domain (порты), config
src/config         ничего не импортирует из src
```

Контексты домена `projects`, `tasks`, `github`, `progress` не импортируют друг друга: связь только событиями, общий код — `src/domain/shared`. Подробно — [`docs/pda/07`](docs/pda/07-architecture.md).

## Запреты

1. **Тип события мимо реестра** и строковый тип в `emit` или `on` (S-3). Сгенерированный файл руками не правится.
2. **Правка схемы существующего события.** Только `version + 1`: в журнале лежат факты прошлой версии.
3. **Доменное правило вне `src/domain`.** Проверка роли, перехода статуса или застоя в хендлере — нарушение, даже если работает.
4. **Число в домене** (S-8). Порог — константа в `src/config` вместе с карточкой в 05.
5. **Системное время в домене** (S-10). Только `Clock`.
6. **Любая запись в GitHub** (INV-21): ни issues, ни PR, ни комментариев, ни меток.
7. **Обход guard доступа** (INV-16): бот отвечает только корню и участникам проекта.
8. **Запись в журнал мимо `emit`** (INV-28): журнал только дополняется.
9. **Новая зависимость без согласования.** Пакет — отдельным коммитом с обоснованием.
10. **Ослабление проверки CI ради своей задачи.** Мешает проверка — остановка и запрос решения.
11. **Правка и удаление якорей** `{R-xxx}` и `{ctx}` в ТЗ. Текст атома меняет автор ТЗ, якорь остаётся.
12. **Реализация того, чего нет в атомах issue.** Нужное, но не записанное — новая issue или `clarify`.
13. **Достраивание пробела ТЗ.** Пробел поднимается как `clarify` и закрывается правкой ТЗ, а не кодом.
14. **ID атомов в коде приложения.** Трасса строится по ссылкам соседних слоёв; исключение — название рендер-теста для атома `view`.

## Порядок работы

1. **Сначала спека.** Задача — issue из [`docs/backlog/`](docs/backlog/README.md): её чек-лист «Атомы ТЗ» и есть объём работы, раздел «PDA» — инварианты и события, которые она затрагивает. Текст атома — в ТЗ, цепочка — `npm run tz:trace`.
2. Нужны новое событие, сущность, связь или переход статуса — сначала правка `docs/pda/` и `contracts/` отдельным коммитом, потом код.
3. Реализация: домен → события → проекции → интерфейс. В обратном порядке правила расползаются по хендлерам.
4. Тесты на затронутые инварианты — в той же задаче.
5. Перед сдачей — `npm run ci` локально.

## Definition of Done инженерной задачи

- код реализован, в домене нет `any`;
- на каждый затронутый инвариант есть тест, имя которого начинается с его ID;
- реестр событий обновлён, сгенерированный файл совпадает с повторной генерацией;
- поменялся порог — обновлены `src/config` и карточка в 05;
- появился механизм — обновлён реестр механизмов в этом файле;
- все проверки CI зелёные, ни одна не отключена и не ослаблена;
- все атомы issue отмечены; неотмеченный — новая issue или `clarify`, не «почти готово»; PR перечисляет закрытые атомы;
- поведение сверено с атомами ТЗ; расхождение исправлено в коде или закрыто правкой ТЗ, но не оставлено молча.

Продуктовая готовность задачи — подтверждение руководителем — другое понятие, оно в ТЗ.

## Когда остановиться

Остановиться и запросить решение, а не изобретать, если:

- задача требует расширить граф домена: сущность, связь, переход статуса;
- нужно новое событие, а его место в реестре неочевидно;
- инвариант из 04 мешает выполнить атом ТЗ — расходятся два источника, выбирать между ними не дело исполнителя;
- проверка CI блокирует изменение, которое кажется правильным;
- атом ТЗ невозможно выполнить средствами Telegram Bot API или GitHub API.

Формат запроса: что требовалось, какое правило мешает, два решения с последствиями. Молча достроенный домен — худший вариант: он проходит ревью и всплывает через месяц.
